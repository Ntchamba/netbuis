Verdict : **CONFORME** (aucun défaut bloquant ; 5 observations). Aucun code du dépôt modifié.

Comptes de test fictifs (+23769999096x) : un prestataire de service (OTP réel, profil créé avec envois `uploads/sign`, validé par un Validateur de test), 4 comptes simples (OTP réel), un Validateur et un Administrateur complet (créés par `manage.py shell`, mot de passe aléatoire, connexion par `POST /api/auth/admin/login/`). ## Observations (aucune corrigée)

1. `…/reports/<type>/<id>/hide|restore|delete/` sur un contenu jamais signalé répond 404 `not_found` (la modération ne porte que sur les contenus signalés ; cohérent avec la description « signalé » de l'OpenAPI, mais un administrateur ne peut pas masquer une publication non signalée).
2. Le propriétaire d'une publication masquée reçoit 404 sur le détail et le fil (elle n'est visible que dans `/api/forum/mine/`) : conforme à l'OpenAPI.
3. Le plafond de 5 publications actives est testé avant la limite quotidienne de 5/24 h : la 6e renvoie SUBSCRIPTION_REQUIRED (400), jamais 429 `daily_post_limit` dans ce scénario.
4. Le motif envoyé à `restore` n'est pas conservé (audit : « restaurer »).
5. Le signalant ne voit plus le contenu mais le contenu reste actif pour les autres jusqu'au 3e signalant (voulu).
