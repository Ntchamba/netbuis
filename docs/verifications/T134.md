# T134 — Appel de bout en bout et latence (vérification de tranche)

Date : 2026-10-22 · Par : orchestrateur · Script : `scripts/e2e_appel/bout_en_bout.mjs` (+ `setup_data.py`)

## Ce qui a été joué
Vrai serveur (uvicorn/ASGI + PostgreSQL local jetable), vrai tableau de bord construit (`dashboard/dist`) dans un vrai Chromium, deux agents connectés par l'écran de connexion. Seul Jitsi est simulé (script `external_api.js` factice). Données fictives.

| Étape | Résultat |
|---|---|
| Deux agents connectés et disponibles (flux SSE ouvert) | OK |
| L'appelant lance l'appel (`POST /api/calls/sessions/`) : salle + jeton Jitsi renvoyés | OK |
| Fenêtre d'appel entrant sur les deux tableaux de bord, avec le nom du commerce | OK |
| Aucun numéro dans la fenêtre de sonnerie | OK |
| L'agent 1 répond : la fenêtre de l'agent 2 se ferme (un seul gagnant) | OK |
| L'agent 1 entre dans la salle (domaine et jeton du serveur) | OK |
| « Voir la fiche » : nom du commerce, numéro du commerce, numéro de l'appelant (D-30) | OK |
| Fin d'appel par l'appelant : la salle se ferme chez l'agent, les numéros disparaissent | OK |
| Aucun agent disponible : réponse `unavailable` sans salle | OK, 52 ms |
| Numéros dans les réponses vues par le navigateur | seulement `/api/admin/calls/sessions/<id>/context/` |
| Aucun numéro dans `/api/calls/history/`, `/api/me/`, `/api/search/` | OK |

## Latence (D-26) — 30 appels, boucle locale
Du moment où l'appelant envoie sa demande jusqu'à la fenêtre **peinte** chez l'agent : min 42 ms · p50 53 ms · **p95 60 ms** · max 61 ms. Cible : < 1 s.

## Non vérifiable ici (pour Jeff)
- Audio réel, connexion Jitsi réelle (1 à 3 s attendues pour établir l'audio), serveur Jitsi non choisi (D-28).
- SDK Jitsi Android sur téléphone, micro, petite fenêtre (procédure dans `docs/TESTS_JEFF.md`).
- Latence sur réseau mobile réel (3G/4G du Cameroun) et derrière Railway (proxy, `NUM_PROXIES`, SSE non mis en mémoire tampon par le proxy).
- Son de la sonnerie dans un navigateur réel.
