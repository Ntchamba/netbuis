## Points ouverts (aucun corrigé, à décider par l'orchestrateur)

1. **Dashboard, page Demandes (défaut d'interface, mineur).** Valider ou rejeter la dernière demande de la dernière page : la page se recharge sur `GET /api/admin/requests/?type=business&page=51&page_size=20`, devenue hors limites (la file passe de 1001 à 1000, donc 50 pages) → 404 (visible dans le journal du serveur). L'interface garde alors la carte déjà traitée (avec « Valider » et « Rejeter ») et « Page 51 sur 51 ». Le `useEffect` ne gère que « page vide », pas le 404. Fichier : `dashboard/src/modules/businesses/pages/BusinessesPage.tsx` (lignes 57 à 60).
2. **Journal du serveur : adresses d'envoi non masquées.** Les lignes `PUT /api/uploads/local/<jeton signé>/` (stockage local de développement) apparaissent en clair ; elles ne sont pas couvertes par `apps/admin_panel/log_filters.py` (qui masque `private-files`). Jetons à usage unique, déjà consommés (204), valables 5 min, dev seulement : faible gravité.
3. **`dashboard/.env.example`** donne `VITE_API_BASE_URL=http://localhost:8000/api`, mais `src/api/endpoints.ts` ajoute déjà `/api/` : avec cette valeur les appels partent vers `/api/api/…` (404 constaté). La bonne valeur est `http://localhost:8000`.
4. **Observations :** (a) refresh d'un compte bloqué : 401 `token_invalid` et non 403 `account_blocked` (comportement correct, car les jetons sont révoqués avant) ; (b) un SMS est quand même émis vers un numéro bloqué à la demande de code (réponse 202 uniforme) ; (c) en développement, `photo_url` / `representant_photo_url` sont des chemins relatifs `/media/…` : le navigateur du dashboard (autre origine) ne les résout pas (images cassées en dev) ; (d) l'ouverture du détail d'un compte par l'Administrateur complet crée à chaque fois une ligne `consultation_numero` (voulu).
